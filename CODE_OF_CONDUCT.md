# Code of Conduct

goat-client is an Apache-2.0 open-source project; this Code of Conduct
applies to all project spaces — issues, pull requests, discussions, and
any synchronous channels we run. It mirrors the policy of our sibling
repo goat-trunk
([`dlf-dds/DesertBreadBird`](https://github.com/dlf-dds/DesertBreadBird/blob/main/CODE_OF_CONDUCT.md))
so contributors crossing between the two see one consistent standard.

## Expectations

- Engage with respect and good faith. Disagree on substance; do not
  attack people.
- Assume contributors are acting in good faith until evidence proves
  otherwise.
- Welcome newcomers. The project is technically dense; first questions
  are valid questions.
- Critique work, not the person doing the work. Reviews are about the
  artifact under review.
- Take ownership when you make a mistake; help each other learn from
  them.
- Respect the boundaries of project scope. Off-topic content belongs
  elsewhere.

## Unacceptable behavior

Behavior that targets, threatens, demeans, or harasses other
participants is grounds for removal. Reporters do not need to enumerate
the form it took for the report to be valid.

## Reporting

Report concerns via
[GitHub Private Vulnerability Reporting](https://github.com/dlf-dds/goat-client/security/advisories/new)
— the same private channel used for security disclosures. A dedicated
mailbox is queued for provisioning; until it lands, the GitHub private
channel is the only stable route.

Reports are read by maintainers and held in confidence. Reporters will
be told what action was taken; respondents will be told what was
reported and given a chance to respond.

## Enforcement

Maintainers may, at their discretion: ask for changes, edit or remove
content, restrict participation in specific spaces, or remove a
participant from the project. Action is proportionate to the behavior
and to whether prior guidance has been ignored.

## Scope

This document covers conduct in project spaces. Conduct outside project
spaces is in scope when it materially affects participants' ability to
engage with the project.

## License-context standards

This is an Apache-2.0 project (see [`LICENSE`](LICENSE)). Contributors
who carry their own institutional codes of conduct (employer policies,
upstream community standards, etc.) are expected to apply the *stricter*
of those and this one in project spaces — there is no precedence
question; both bind.
